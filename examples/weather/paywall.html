What happens when it pays

  1. 402
    The unpaid request. GET /weather answers 402 with the terms above in PAYMENT-REQUIRED.
  2. sign
    The buyer signs. A bank send of {{.Coin}} to the payee, signed by the buyer's wallet or key and placed in PAYMENT-SIGNATURE. Nothing is broadcast yet.
  3. retry
    The same request, paid. The seller hands the signed transaction to its facilitator, which checks it against the terms. Only then does the weather get produced.
  4. 200
    Settled, then served. The facilitator broadcasts the transaction, then the weather goes out and PAYMENT-RESPONSE carries the transaction hash. A resource that fails is never charged; a settlement that fails withholds the response.

Pay it from code

A script or an agent pays the same way. buy.mjs, beside this seller in the repository, is one such client. One command runs it without a clone.

READ IT BEFORE YOU RUN IT

The script signs with the mnemonic you give it. Read it first, and never give it a mnemonic that holds anything: use a throwaway key. A session key works too, with X402_SESSION_MASTER set to your address; the chain holds it to its spend limit.

  1. Read the script. examples/weather/buy.mjs is the whole buyer the commands below run.

  2. Make a throwaway key. This prints a new mnemonic, its address and the command that pays this page with it, and saves none of them.

    npx github:gnoverse/x402#client/v0.5.0 --new-key <this page's URL>

  3. Fund its address{{with .Faucet}} at {{.}}{{end}} with test GNOT on {{.Network}}: {{.Amount}} {{.Unit}} for the weather, and the network fee on top.

  4. Pay with the command step 2 printed. It looks like this, and prints the transaction and the weather.

    X402_MNEMONIC='<mnemonic>' npx github:gnoverse/x402#client/v0.5.0 <this page's URL>

Both commands need git and Node 22.18+ or 24.11+. Running the buyer from a clone, or against another node, is in the weather example's README.

A stock x402 client pays in gno after two lines: register the scheme, and admit ugnot (a millionth of a GNOT) to its spend controls, capped per request.

import { ExactGnoScheme } from "@gnoverse/x402-gno/exact/client";

const client = new x402Client()
  .register("gno:*", new ExactGnoScheme(wallet))
  .setSpendControls({
    allowedAssets: [{ network: "gno:*", asset: "ugnot", maxAmountPerPayment: "1000000" }],
  });

Sell an endpoint in gno

Testnet only. The mechanism is unaudited and pre-release; do not point it at real funds.

A seller lists gno among the ways a route accepts payment, and the ecosystem's x402 middleware does the rest: it prices the route, answers 402 and reads the payment. Only the scheme is gno's. In Go:

routes := x402http.RoutesConfig{
    "GET /weather": {
        Accepts: x402http.PaymentOptions{{"{{"}}
            Scheme:  "exact",
            PayTo:   "<your g1 address>",
            Price:   x402.AssetAmount{Asset: "ugnot", Amount: "250000"},
            Network: "{{.Network}}",
        }},
    },
}

handler := nethttpmw.X402Payment(nethttpmw.Config{
    Routes: routes,
    Facilitator: x402http.NewHTTPFacilitatorClient(&x402http.FacilitatorConfig{
        URL: facilitatorURL,
    }),
    Schemes: []nethttpmw.SchemeConfig{{"{{"}}
        Network: "{{.Network}}",
        Server:  gnoexact.NewExactGnoScheme(),
    }},
})(mux)

The facilitator holds no key: it checks each payment and broadcasts what the buyer signed. One serves the onyx testnet at https://facilitator.onyx.testnets.gno.land, or run your own. The whole seller behind this page is examples/weather/main.go.
